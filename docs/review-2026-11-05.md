## 已确认并修复的发现

| 问题 | 证据与影响 | 修复 |
| --- | --- | --- |
| ChatGPT 官方用量链接失效 | 真实 Chrome 中，旧 `/codex/settings/usage` 被重定向回首页；官方“用量 → 管理用量”进入 `/settings/usage` | 更新官方入口，保留新旧设置路径的输入框排除规则 |
| Gemini 校准误读隐藏内容 | 新增用例中隐藏父容器内的 95% 覆盖了可见的 10%；隐藏百分比也可能干扰匹配 | 计算祖先可见性，仅读取可见文本，排除 `hidden` / `aria-hidden` / CSS 隐藏元素 |
| Gemini 账号来回切换接收旧结果 | A → B → A 的请求延迟返回时，原实现仅比较账号字符串，接受了切换前的 99% | 每次账号范围变化递增版本；响应必须同时符合当前 URL 和版本 |
| 刷新间隔超出浏览器定时器范围 | `Infinity` 或极大 Gemini 间隔可传入定时器，浏览器可能将溢出延迟降为极短周期；Codex 位运算也会截断大整数 | 内容脚本和弹窗共同限制最大间隔为一天，移除 32 位截断，保存后回显有效值 |
| Gemini 官方用量页弹窗一直 Loading | 此页面按设计不发起额度请求，但初始弹窗仍展示等待状态 | 立即提示返回对话页刷新，避免假装正在加载 |
| Codex 重复窗口静默覆盖 | 两个窗口映射为同一周期时，后一个值覆盖前一个，无法判断正确目标 | 将冲突周期保留为未知 |
| Codex 非法重置时间进入 UI | 超大有限 epoch 乘以 1000 后变为 Infinity，导致无效日期/倒计时 | 检查转换后的数值及 JavaScript 日期范围；无效值作为未知 |
| sharp 构建依赖安全公告 | `npm audit` 报告 sharp <0.35.5 的高危 librsvg 公告 [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w) | 升至 sharp 0.35.5 及对应 libvips，更新锁文件；审计清零。此依赖用于本地图标构建，不随扩展运行时代码分发 |

- **视觉**：检查了两个真实页面的深色布局，以及自动化生成的浅色、深色、窄屏、错误和缺失窗口状态。实时页面的视口覆盖设置未实际改变已有标签页尺寸，因此不将其计为真实网站手机宽度测试；390px 实际扩展加载测试及 240–1440px 合成布局测试单独记录。

## 明确的边界与后续操作

- 真实 Chrome 实测针对用户已经安装的版本。浏览器工具的 URL 策略拒绝 `chrome://extensions`；虽然用户随后明确授权扩展管理页访问，工具仍只开放 HTTP/HTTPS。本次没有绕过该限制，因此修订后的源码尚未在用户现有配置中重载。
- 若现有扩展通过本项目目录加载，打开 Chrome 的扩展管理页面，点击 QuotaLens 的重新加载，然后刷新 ChatGPT 与 Gemini 标签页，即可使用修改后的源码。若从发布压缩包安装，应先将扩展切换到更新后的代码目录或重新打包。
- Claude 的真实登录、订阅及页面行为按要求暂未验证。
- 内部 API 和页面结构可能继续变化；自动化和当前实测不能保证未来兼容性，也不能证明项目不存在所有潜在错误。
- MAIN 与 ISOLATED 的 `window.postMessage` 桥不是与宿主网页之间的信任隔离：同源页面脚本可观察或伪造该通道。当前实现限制为标准化额度值与 RPC 标识，不跨桥传递令牌；可信宿主页面仍是其运行前提。
- 默认轮询仍按可见标签页独立执行，多个同时可见窗口会增加请求量。现有 429 冷却和请求去重仅在单标签页内生效；此限制已在数据源说明记录，本轮未改成跨标签页调度。
